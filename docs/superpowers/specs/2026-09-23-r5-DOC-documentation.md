## 2. The EMS pattern (what we copy, what we change)

What EMS does (studied read-only):

| # | EMS practice | Where |
|---|---|---|
| 1 | Three layers: **raw schema dump** (`db-schema/`), **knowledge layer** (`knowledge/`, code-free logic), and **design/plan docs** loose in `docs/*.md` (plans, not truth). | `EMS SYSTEM/docs/` |
| 2 | The schema is a generated SQL dump, split by concern: `01-extensions` · `02-enums` · `03-tables/<domain>.sql` · `04-indexes` · `05-constraints` (all FKs) · `06-functions/<domain>.sql` (full bodies). Header `Generated: <date>`, regenerated by `npm run dump-schema`. | `db-schema/` |
| 3 | The knowledge layer has **one file per domain** (billing, tariffs, meter-readings, access-control, data-model, i18n …). Each file tells the *whole* story: every branch, constant, edge case and quirk, with a ToC. No code at all. | `knowledge/*.md` |
| 4 | `_map.md` is THE index: per file, "what's inside" plus the **questions it answers**. It also has an explicit **"Not yet covered"** list, so gaps are visible. | `knowledge/_map.md` |
| 5 | Every file ends with a **source anchor** ("Grounded in": function/service *names*) and a **validation stamp** (`Last validated: date, branch, commit SHA`) + "re-verify if X changes". | footer of each file |
| 6 | Updates are **diff-based**: the stamp's SHA is the baseline, `git diff <SHA>..HEAD -- <grounded paths>` decides what to re-read. An adversarial "verification protocol" pass tries to refute each draft. | `.claude/agents/sigmatec-knowledge.md` |
| 7 | A dedicated curator agent (`sigmatec-knowledge`) owns the layer. Primary source = code/SQL only; specs and CLAUDE.md are *leads*, not sources. | same |
| 8 | Graph side: graphify node-link JSON. Each node carries `id`, `label`, `file_type` (code/document/rationale), **`source_file` + `source_location` (`L<n>`)**. Edges carry `relation` + `confidence` (EXTRACTED/INFERRED/AMBIGUOUS). `manifest.json` = scanned files + mtime/hash for incremental builds. `source-info.json` = repo, branch, **commit**, counts. | `EMS Graph/` |
| 9 | Freshness is by commit: `graph-update-log.md` records each check ("prod still at d10bacf, left as-is"). Rebuilds run from a **detached worktree** and prune junk nodes afterwards. `_START_HERE_FUTURE_CLAUDE.md` is the cold-start door. | `EMS Graph/` |
| 10 | The weakness EMS admits: AST-only rebuilds cover docs **shallowly** (16 `knowledge/` nodes vs 231 after the last LLM pass). The rich doc layer is only in an archived semantic snapshot. | `_START_HERE…`, `archive/2026-07-07-semantic/README.md` |

**What we copy:** the layering (generated schema, per-domain truth docs, plans kept apart), the `_map`-style index with "questions it answers" and "not yet covered", the Grounded-in + commit stamp, diff-based updates, and primary-source-only verification.

**What we change, and why:**
- **Schema as Markdown per table, not SQL dumps.** SQL gives the graph nothing new: `fix_graph.py` already regexes `db/*.sql`. The gap is the *live* DB (tables and policies that exist in production but not in any `db/*.sql`, or differ from them). A Markdown page per table, generated from `information_schema` + `pg_policies`, gives each existing `table:<name>` / `policy:<name>` node a real `source_file`. Today every `table:` node has `source_file: null`.
- **Code anchors are allowed (and required) in written docs.** EMS bans code and anchors by *names only*. Our graph keys on `fn:<name>@<path>` and `file:<path>`. So a written claim anchored as `` `app/src/lib/alerts.ts#visitAlerts` `` maps straight to a graph node and becomes an EXTRACTED `documents` edge, with no LLM guessing. We still include **no code snippets**.
- **Docs don't depend on the LLM to reach the graph.** EMS's doc coverage vanished when the semantic pass wasn't re-run. Ours goes through a deterministic pass (§8.2): front-matter + anchors + links become edges on every `rebuild.py`, for free. Sonnet only adds the meaning of the prose.
- **Enforced, not aspirational.** EMS's "not yet covered" is hand-kept. Ours is computed: `test-docs.mjs` fails when a live table, an edge function or a source file is claimed by no doc (§9).
- **Public repo.** EMS docs are private. Ours are public: no secrets, no cron command bodies, no evaluative security findings (§10).

## 4. Front-matter, IDs and the linking convention (what the graph keys on)

### 4.1 Front-matter (every file under `docs/system/`)

```yaml
---
doc_id: module:visits            # graph node id this doc DEFINES (see 4.2)
doc_type: module                 # module | table | edge_function | flow | system | design | operations | generated
title: ביקורים וסיכום ביקור (Visits)
generated: false                 # true = whole file is generator output; "partial" = has GENERATED blocks
generator: null                  # e.g. scripts/docs/gen-schema.mjs when generated
code:                            # files/globs this doc is the owner of (drives coverage + stale detection)
  - app/src/islands/Field.tsx
  - app/src/lib/visitDraft*.ts
  - app/src/lib/field.ts
tables: [visits, visit_drafts, field_checkins]
edge_functions: [push-send]
flows: [visit-summary-chain]
roles: [עידן, עמיחי, אביאם, ניתאי, viewer]
specs:                           # history/decisions, newest first
  - docs/superpowers/specs/2026-09-23-r5-V-visit.md
  - docs/superpowers/specs/2026-09-23-visit-summary-chain-design.md
requirement_source: "product/SRS-סיגמה-2.0.md §3.4"
last_validated: { date: 2026-10-xx, branch: main, commit: abc1234 }
---
```

Rules:
- `doc_id` is unique across the tree (checked).
- `code:` globs across all module docs must **partition** `app/src/**`, `supabase/functions/**`, `db/*.sql` and the remaining `js/src/*`. Every file is owned by exactly one module; shared helpers go to `shell-and-access` or `_shared`. This is what makes "not yet covered" computable.
- `last_validated.commit` is the EMS-style baseline for diff-based updates (§9.3).

### 4.2 Node-ID vocabulary (reuse the graph's existing prefixes; add four)

| Prefix | Meaning | Status |
|---|---|---|
| `file:<repo-path>` | a file (code or doc) | existing |
| `fn:<name>@<repo-path>` | a function/symbol | existing |
| `table:<name>` / `table:<schema>.<name>` | DB table | existing (`fix_graph.py` §F/G) |
| `policy:<name>` | RLS policy | existing (§L) |
| `ext:<name>` | external system (EMS API, Google, GitHub, Clockify) | existing |
| `person:<name>` | team member | existing |
| **`module:<slug>`** | business module (a doc_id) | new |
| **`flow:<slug>`** | cross-module chain | new |
| **`alert:<mode-or-key>`** | a push mode / bell alert (matrix row) | new |
| **`term:<slug>`** | glossary entry (Hebrew term) | new |

### 4.3 Anchors inside prose

| You write | Means | Graph edge emitted (deterministic, §8.2) |
|---|---|---|
| `` `app/src/lib/alerts.ts#visitAlerts` `` | the symbol `visitAlerts` in that file | `file:<doc>` —`documents`→ `fn:visitAlerts@app/src/lib/alerts.ts` |
| `` `supabase/functions/push-send/index.ts` `` | a whole file | `documents` → `file:…` |
| `[visits](../schema/public.visits.md)` | a table (always a link to its schema page) | `documents` → `table:visits` |
| `[visit-summary-chain](../flows/visit-summary-chain.md)` | another doc | `references` → that doc's `doc_id` |
| `policy:visits_write` (backticked) | a policy | `documents` → `policy:visits_write` |

- **Written docs use `path#symbol`, never `path:line`.** Line numbers rot on every edit, symbols rarely do. The check resolves the symbol (§9.1). **Generated docs** may emit `path:line`, because they are regenerated.
- `source_location` for doc-emitted edges = the doc line (`L<n>`), so `ops_graph.py explain` can quote the claim.
- The relations used are only ones the graph already has (`documents`, `references`, `owns`, `reads_writes`, `groups`, `implements`, `tests`), so `ops_graph.py` works unchanged.

### 4.4 Footer (EMS convention, kept for humans)

Every written doc ends with:

> *Grounded in:* `path#symbol`, … · *Last validated:* <date>, `main`, commit `<sha>` · *Re-verify if:* <paths/globs>.

## 5. Templates per doc type

`docs/system/_templates/` holds one skeleton per type (committed in DOC-0; excluded from the graph corpus). Sections marked **G** sit between `<!-- GENERATED:<name> -->` … `<!-- /GENERATED:<name> -->` markers. Generators rewrite only inside those markers, so written prose survives regeneration (the same idea as `integration-map.annotations.md`, but inline).

### 5.1 Module (`modules/<slug>.md`)
1. **What it is.** One paragraph, with Hebrew UI names (`סיכום ביקור`, `🚚 תעודה`).
2. **Who uses it.** Role × action table. Links `roles-and-permissions.md` rows; no duplicated matrix.
3. **Screens and entry points.** Page / island / sheet, header action, ⋯ עוד registry entry, deep links, push taps that land here.
4. **Behaviour: the complete story** (EMS rule: every branch, default, constant, threshold, ordering rule and edge case). Prose, tables, decision trees and formulas, anchored with `path#symbol`. No snippets.
5. **Data.** Tables read/written, and what each column *means* for this module (the schema page has types; this has meaning). Links each table.
6. **Rules and locks.** E.g. `editableUntil(date)`, past-data lock, "attendance only for אביאם/ניתאי in מי ביקר".
7. **Integrations** **G** (from `integration-map.mjs` `analyze()`): edge functions + modes, bus events, bridge surfaces (if any survive), EMS endpoints, query keys.
8. **Alerts and pushes it raises.** Links to the `alerts-matrix.md` rows (no copy).
9. **Load-bearing quirks** (EMS "known quirks"), each marked *intentional* or *bug, tracked in backlog*.
10. **Tests** **G**: test files that import/cover the owned code (from graph `tests` edges + Playwright specs by name).
11. **Specs and decisions.** Links to specs and decisions-log rows, newest first. These are history, not truth.
12. **Inventory** **G** (from the graph): owned files, exported symbols, tables touched, inbound dependents.
13. Footer (§4.4).

### 5.2 Table (`schema/<schema>.<table>.md`), fully generated
- Front-matter `doc_id: table:<name>`, `generated: true`, `introspected_at`, `introspection_commit`.
- **Purpose**: `obj_description` (live `COMMENT ON`) if present, else `_purposes.yml`, else a visible `⚠ no purpose recorded` that `test-docs` counts.
- **Columns**: name · type · null · default · FK → (link) · note (column comment or overlay).
- **Keys and indexes**: PK, uniques, indexes.
- **Relations**: FKs out, FKs in (links).
- **RLS**: enabled / forced; a policy table: name · command · roles · permissive/restrictive · `USING` · `WITH CHECK` · **defined in** (the `db/*.sql` files whose `create policy` matches, same regex as `fix_graph.py` §L). Facts only.
- **Triggers** on this table (links `_functions.md`).
- **Used by** (from `integration-map.mjs` `analyze()` + graph `reads_writes` edges): `file:line` · read/write · module.
- **Migrations**: `db/*.sql` files that create/alter it.
- **Drift vs `db/`** (neutral wording): columns/policies live but in no migration, or in a migration but not live.

### 5.3 Edge function (`edge-functions/<fn>.md`)
- **G:** modes (every `body.mode === "…"` branch, with `index.ts:line`), auth check per mode (e.g. `emsValid` / `byCron`), secret **names** read (`Deno.env.get("…")`), tables touched, outbound hosts, callers (client `functions/v1/<fn>` sites + cron jobs targeting it).
- **W:** purpose; per-mode behaviour, inputs and outputs; failure modes and retries; the deploy note (`deno check` gate, redeploy after a secret change, the handoff convention); mirrors (e.g. `field.ts` / `alerts.ts` byte-copied from `app/src/lib`).

### 5.4 Flow (`flows/<slug>.md`)
- Trigger · actors · preconditions.
- A mermaid `sequenceDiagram`.
- Steps table: # · module · action (`path#symbol`) · table / fn / push · failure and recovery.
- Invariants (e.g. "stock never double-deducts for a pre-breakpoint September edit").
- The tests that pin the chain (e.g. `test-visit-summary-chain.mjs`, the Playwright spec).
- The modules involved (front-matter `modules:`, which emits `flow:` —`groups`→ `module:` edges).

### 5.5 Roles and permissions (`roles-and-permissions.md`)
- **G** people → role(s) (from `app/src/lib/people.ts`, `caps.ts`, `app_admins`, the X `staff_identities`).
- **G** role × page (`canShowPage.ts`), role × capability (`caps.ts`), role × table × command (from live `pg_policies`: anon / authenticated / viewer-restrictive / name-claim), role × alert (from the matrix).
- **W** the model in prose, and which layer enforces what (UI gate vs RLS vs edge fn).

### 5.6 Alerts matrix
Owned by package X (X-L5: content + `test-alerts-matrix.mjs`). DOC only `git mv`s it to `docs/system/alerts-matrix.md`, updates the test's path, and adds front-matter + `alert:<mode>` ids per row. Nothing is rewritten, so there is no second matrix.

### 5.7 Glossary
Columns: Hebrew term · English/code identifier(s) · table.column · where on screen · note.

It is seeded from SRS §9, `whisper-glossary.md` and the UI strings in `app/src/**`. Examples: סיכום ביקור ↔ `visits` / `Field.tsx`; תעודת משלוח ↔ `delivery_certs`; צריבות ↔ `meter_burns`; מי ביקר ↔ `visitors`; חודש עבודה / חודש מלא; ללא אפיון.

`test-docs` checks that every code identifier named in the glossary still exists.

### 5.8 Design / operations / overview
Written with the standard footer. `tokens.md` and `components.md` are fully generated.

## 8. Writing, then the graph

### 8.1 Writing (DOC-1)
- **Writers:** one Sonnet agent per module or flow, run in parallel batches of ~6. Each gets its template, the front-matter `code:` globs, the owning specs as *leads*, and the EMS rule: **primary source is the code; every claim anchored; the whole story, no summaries; no snippets.**
- **Refutation pass (EMS verification protocol):** a second Sonnet agent per doc tries to refute ~10 claims against the code and fixes what fails.
- **Opus review:** Opus reviews the module and flow set for cross-doc contradictions and for any fact that has two homes.
- **Order:** generated layer first (schema, edge-fn G-sections, roles, inventory), so writers link to real pages; then modules; then flows (which link modules); then system-level docs; then `README.md` regenerated last (EMS: "update `_map.md` last").

### 8.2 Deterministic doc → graph pass (built in DOC-0)
New `docs/ops-graph/doc_links.py`, called by `rebuild.py` after step 3 (merge), before `fix_graph.py`:
- Parse front-matter: emit the `doc_id` node (`module:`/`flow:`/…) + `file:<doc>` —`documents`→ `doc_id`; `module:` —`owns`→ each `file:` matched by `code:`; —`reads_writes`→ `table:`; —`references`→ edge fn files; `flow:` —`groups`→ `module:`.
- Parse anchors (§4.3): `documents` edges with `source_location` = doc line, confidence `EXTRACTED`, score 1.0. An unresolvable anchor emits nothing (the check in §9 already failed it).
- Table pages: give each `table:<name>` node `source_file` = its schema page, and relabel policy nodes from the **live** definition (replacing the `db/*.sql` first/last guess of `fix_graph.py` §L when a live JSON exists).
- **Retired docs:** today `fix_graph.py` §E tags nodes of missing files `planned`. Add a rule: a `document` node whose `source_file` is under `docs/` and gone from disk is **dropped**, not tagged. The retired docs' old knowledge must not linger as "planned".

### 8.3 Semantic re-sync (DOC-2)
1. **Write down the extraction prompt** (it isn't in the repo today): `docs/ops-graph/EXTRACTION_PROMPT.md`. It holds the graphify subagent prompt + the OPS id conventions (`file:`, `fn:<name>@<path>`, `table:`, `policy:`, `ext:`, `person:`, and the four new prefixes), recovered from the existing chunk JSON. Future re-syncs then use exactly the same prompt.
2. **Corpus:** add `docs/system/**` (minus `schema/*.md`, `generated/*`, `_templates/`, which the deterministic pass already covers fully) and `docs/product/**`, `docs/usage/**` to `.graphify_detect.json`. Remove the retired paths.
3. **Generation 3:** new chunk manifests `.chunks/chunk_NN.txt`, ~13 written docs each, so **~4 Sonnet chunks for ~50 written docs**. Add `"3": <first NN>` to `generations.json`, so the newest generation owns those files and older doc knowledge is replaced, not piled up. Code files changed since the last sync (all of round 5) get their own gen-3 chunks per the README re-sync procedure; that is round-5 self-check step 4, done here once more at the end.
4. `python docs/ops-graph/rebuild.py` → asserts pass.
5. **Opus audit** (a separate agent that didn't write the docs):
   - Stratified sample of **40 edges**: 15 doc→code `documents`, 8 `reads_writes` doc/table, 7 flow `groups`/steps, 5 policy labels vs live, 5 `module:` `owns`.
   - Each is verified against the source and the live JSON. **Pass bar: ≤ 2 false, 0 hallucinated nodes.** A fail sends the owning chunk/doc back, then a re-audit of a fresh 40.
   - Coverage asserts: every live table has a `table:` node with a schema `source_file`; every edge fn has a doc; every `module:` has ≥ 1 `owns` edge; `ops_graph.py table visits` names the schema page + module + flow.
   - The audit writes `GRAPH_AUDIT.md` **locally only** (`<project>/תוצרים/YYYY-MM-DD — ממצאי OPS GRAPH/`), per the public-repo rule. The committed README gets only the pass line.
6. **Update:** `ops-graph/README.md` (last semantic sync, counts, the new prefixes, and a "docs/system is the truth layer" note), `INDEX.md` Files pointer, CHANGELOG, backlog.

## 9. Keeping it true

### 9.1 `test-docs.mjs` (in `npm test`)
- Front-matter parses; `doc_id` is unique; `doc_type` is valid.
- Every `path#symbol` resolves: the file exists and the symbol is declared (a regex for `function|const|let|class|export … <symbol>`).
- Every `path` / relative link resolves.
- **Coverage:**
  - every table in `_introspection.json` has a page;
  - every `supabase/functions/*/` has a doc;
  - every file under the partition roots (§4.1) is owned by exactly one module (a double claim fails; the unclaimed list is printed and must be empty at DOC exit).
- No written doc (outside `schema/`) mentions a table name missing from the introspection.
- `npm run docs:check`: no generated file is stale.
- The retired paths from §7 do not exist (so a duplicate can't come back).

### 9.2 Secret and exposure guard
- `qa/gitleaks` runs over `docs/system/**` in the same test.
- `gen-schema` hard-refuses to emit `cron.job.command`, function bodies, or any column *values*.

### 9.3 Diff-based updates (EMS incremental mode, automated)
`scripts/docs/stale.mjs` lists, for each written doc, the commits since `last_validated.commit` that touched its `code:` globs.
- An empty list means current.
- Otherwise it prints the paths, so the updater reads only those hunks (the `sigmatec-knowledge` Update-mode procedure, step 4–6).
- It runs at every checkpoint.

**Optional (proposed, not in scope without עידן's yes):** an `ops-knowledge` curator agent in `.claude/agents/`, modelled on `sigmatec-knowledge`.

## 10. Public-repo rules for this package
- **Never in a doc:** secret values, JWT/anon/service keys, the viewer PIN, cron command bodies (they carry `Authorization` headers), function bodies, row data.
- **Secrets by NAME only**, per function (`GH_TOKEN`, `BACKUP_KEY`, …).
- **Policies stated as facts**, the same information already public in `db/*.sql`. **No evaluative security findings** ("X is readable by anon, which is bad"). Those go to the local `BROKEN.md`.
- Where a generated drift line would reveal an open gap, it says "differs from `db/` — see local findings", not the detail.
